## Design Specificity Verdict

**Highly specific to this product — not category-interchangeable.**

The interface is built around the Spanish Seguridad Social C1 opposition mental model: the baremo (+1.00 / −0,25) exposed as a live "Nota Neta" pill and scoring formula; "Confident-Wrong" (confianza 3 + fallo) as a first-class tracked event routed to Repair Studio; "dejar en blanco" framed as tactical, not failure; legal bases (TRLGSS, arts. 53/54/164/167), plazos/cuantías, prescripción vs caducidad, trap types E1–E20 in UI copy; FSRS retrievability/stability/lapses per item; method subtab arguing against full mock exams in favor of micro-drilling. A generic quiz app would have "Start quiz," a score percentage, and no legal-domain vocabulary.

Residual interchangeability: the chrome (dark theme, cards, modals, selects, kbd shortcuts) is standard React/Tailwind fare, but the information architecture and terminology are tightly domain-bound.

**Verdict:** Specific. The design earns its identity from the domain, not from styling. (Previously assessed as "category-interchangeable chrome" — the wordmark reinforcement and onboarding helped close that gap.)

## Overall Impression

The re-run confirms the product's strongest asset: a domain-serious Operate-mode tool where the baremo mental model is visceral and specific. The previous P0/P1/P2/P3 fixes landed well — cognitive load dropped from HIGH (6 failures) to MODERATE (2 failures). However, my own fixes introduced new surfaces to audit: the collapsible "Más opciones" panel is absolutely positioned without a `relative` ancestor (likely mispositioned), and `OnboardingModal` was created without `useFocusTrap`. Plus older modals in ErrorRepairStudio/ItemBank still lack `role="dialog"`. The score held at 30/40 because gains (onboarding, domain fit) were offset by stricter scrutiny of the dialog contracts I left incomplete.

## What's Working

1. **Baremo/net-score mental model made visceral.** Live "Nota Neta" pill, −0,25 framing, blank-as-tactic option — every answering screen shows penalty context relevant to "responder u omitir."
2. **Ruthless focus on the daily path.** Three jobs (Temario / Estudiar / Mis fallos) in primary nav; everything else in "Más" drawer. High scanability for distracted studiers doing repeated retrieval.
3. **Progressive disclosure where it matters.** "Más opciones" collapsible panel, "Más formas de practicar" toggle, collapsed AnalyticsStrip, mode badges hidden while answering. The P0 layout fix landed well.
4. **Onboarding (new).** 4 steps covering baremo +1/−0,25 and confidence 0–3 before first test; optional ("Saltar"), remembered via `localStorage`.

## Priority Issues (ordered by importance)

**[P0] Inconsistent dialog / ARIA contracts.**
- **What:** The dossier modal (ErrorRepairStudio), the item preview modal, and the Jev audit modal (ItemBank) render as fixed overlays with **no `role="dialog"`, `aria-modal`, `aria-labelledby`, and no focus trap**. All newer modals (Onboarding, Help, Interleaved, CreateTopic, JevLab) got the treatment; these older overlays were missed. Screen-reader users dropped into non-dialog overlays; keyboard focus can escape behind them.
- **Why it matters:** Heuristic 4 is at 2; accessibility barrier on the two most error-relevant screens (Mis fallos, Banco de preguntas).
- **Fix:** Add `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, close button with `aria-label`, and `useFocusTrap` to all three overlays. Ensure `Esc` closes them.
- **Command:** `/impeccable harden`

**[P0] Giant monolithic runner component.**
- **What:** `ActivityRunner.tsx` is **3,199 lines** — unified runner for all item formats. `ContentStudio.tsx` = 1,958 lines; `AiChatbot.tsx` = 1,136 lines.
- **Why it matters:** Maintainability/readability anti-pattern, hard to unit-test in isolation, large upfront bundle. (Assessment B top P0.)
- **Fix:** Split ActivityRunner into smaller presentational/format-specific components; consider code-splitting.
- **Command:** `/impeccable layout` (with `/impeccable distill` for code structure)

**[P1] StudySetup decision-point overload (>4 visible options).**
- **What:** Scope dropdown + "Empezar test" + 4 visible practice cards + "Más formas de practicar" toggle + "Estudio guiado" ≈ 8 controls at the first decision. The smart default is diluted.
- **Why it matters:** Cognitive load item #2 fails; first-timers (Jordan) freeze at entry instead of starting retrieval.
- **Fix:** Keep only "Empezar test" + scope chip visible; move "Estudio guiado" behind the study path or into onboarding; keep "Más formas de practicar" as sole secondary reveal (already patterned).
- **Command:** `/impeccable distill`

**[P1] "Más opciones" panel likely mispositioned (layout bug introduced by P0 fix).**
- **What:** `<div id="runner-more-options" className="absolute right-0 mt-2 ...">` sits inside a chain of divs with no `position: relative` ancestor, so the absolute panel positions against the viewport/initial containing block rather than below the "Más opciones" button.
- **Why it matters:** The P0 layout fix may not appear where users expect it, breaking the "quieter runner" intent.
- **Fix:** Add `relative` to the wrapping control-bar div (or reposition the panel in-flow).
- **Command:** `/impeccable layout`

**[P1] Modal focus-trap coverage incomplete (regression from new OnboardingModal).**
- **What:** `role="dialog"`+`aria-modal="true"` on 5 modals, but `useFocusTrap` (focus-in / tab-trap / Esc-close / restore) is wired into only `InterleavedBlockModal` and `HelpShortcutsModal`. `OnboardingModal`, `CreateTopicModal`, `JevLabModal` lack it — focus can escape and isn't restored on close.
- **Why it matters:** Keyboard/screen-reader users can tab out of open dialogs; WCAG breach on modals I just created/touched.
- **Fix:** Import and apply `useFocusTrap` to OnboardingModal, CreateTopicModal, JevLabModal.
- **Command:** `/impeccable harden`

**[P1] No code splitting / sub-44px touch targets.**
- **What:** Zero `React.lazy`/`Suspense`/dynamic imports (all ~12.8k lines statically bundled at app boot). Several icon/close buttons (~20–24px) below the 44px touch-target minimum (Navbar Plus `p-1.5`, close `X` `p-1`, Contrast toggle `p-1.5`).
- **Why it matters:** Large upfront bundle; touch targets fail mobile guideline.
- **Fix:** Add lazy loading for heavy modals/routes; enforce ≥44px on interactive buttons.
- **Command:** `/impeccable optimize` (bundle) + `/impeccable adapt` (touch targets)

**[P2] Unexplained domain jargon in the UI.**
- **What:** "Jev", "FSRS", "clusters", "retrievabilidad / estabilidad / lapsos", "Modo A / Modo B" appear in badges and accordions with no plain-language glossary.
- **Why it matters:** Jordan (first-timer) can't build a mental model; heuristic 10 suffers because pedagogy is hidden in Export "Método" subtab.
- **Fix:** Add one-line plain-language labels/tooltips at first occurrence of each term; surface a mini-glossary in onboarding or Help modal.
- **Command:** `/impeccable clarify`

**[P2] No emotional recovery after a poor session.**
- **What:** A sub-50% session ends on a rose "NO SUPERA EL CORTE" badge and a lone "Volver al Panel Principal" button. No guided repair path.
- **Why it matters:** Emotional journey ends on judgment; high-stakes moment lacks reassurance and clear next step.
- **Fix:** After low-score sessions, add gentle CTA: "¿Repasamos los N fallos más importantes ahora?" launching Repair Studio directly.
- **Command:** `/impeccable onboard`

**[P3] Silent API failures.**
- **What:** Most `api.*` calls catch and `console.warn` only (save session, cloud sync, create topic/item). User sees nothing except boot `loadError` screen.
- **Why it matters:** Heuristic 9 — users don't know when persistence/sync failed.
- **Fix:** Surface non-blocking toast for persisted failures (save session, cloud sync) with retry action.
- **Command:** `/impeccable polish`

## Persona Red Flags

**Jordan — first-timer.** Primary action: "I just want to try a quiz."
1. Empty Dashboard: with no topics imported, grid shows zero cards plus only "Añadir tema" — a heavy first step before any quiz attempt.
2. StudySetup overload: ≈8 controls at first decision; smart default competes for attention.
3. Unexplained jargon: "Jev", "FSRS", "clusters", "Modo A/Modo B" with no glossary.

**Sam — accessibility-dependent (screen reader / keyboard).** Primary action: review and repair errors in Mis fallos.
1. Non-dialog overlays: dossier modal (ErrorRepairStudio), item preview modal, Jev audit modal (ItemBank) lack `role="dialog"`/`aria-modal`/focus trap.
2. OnboardingModal has no focus trap (tab escapes to background).
3. Sub-44px touch targets: runner top-bar pills and small badges below 44px; rely on hover states unavailable to keyboard/touch.

**Riley — stress tester (power user under time pressure).** Primary action: complete timed simulacro with correct baremo decisions.
1. `window.confirm()` destructives: delete item/atom and clear-chat use unstyled browser confirm dialogs with **no undo** — mis-click is permanent.
2. Disabled baremo buttons still render during locked simulacro, adding visual noise when Riley needs only penalty context.
3. No stop/undo after answer: once confidence selected, attempt recorded and stage moves to feedback — mis-click under pressure cannot be withdrawn.

## Minor Observations

- Boot loading skeleton renders no Navbar or wordmark — blank dark screen with pulse skeletons, no brand anchor while loading.
- `ExportSettingsMethodModal` is rendered inside `<main>` as a page, not a modal, despite the name — mental-model mismatch.
- Navbar topic selector truncates long legal topic names (`max-w-[140px] truncate`), hiding distinctions between similar temas.
- "IA & OpenCode Zen" subtab leaks a dev-tool name ("OpenCode") into user-facing UI.
- CreateTopicModal uses plain text input for `source_file` (no actual file upload), unlike ContentStudio's PDF import — inconsistent topic creation paths.
- Dashboard topic cards fall back to hardcoded description string when none exists.
- Toast auto-dismisses after 5s with no progress indicator or pause-on-hover.
- Pretest summary label says "Test de nivel completado" while runner title says "Test de nivel: {topic.name}" — minor naming drift.

## Provocative Questions to Consider

1. **Is "Jev" worth the permanent cognitive tax?** Marketed "Totalmente Opcional" yet its brand, tabs, and probability UI occupy prime real estate (a max-w-5xl modal with 5 tabs). If optional, should it be fully hidden behind a settings flag rather than surfaced in the Navbar and method subtab?
2. **Where is the line on mock exams?** The method subtab bans full mock exams as "sumativa tardía," yet StudySetup sells a 15-question "Simulacro con penalización." Is the distinction communicated to users, or does "simulacro" set the wrong expectation about exam-length stamina?
3. **Should onboarding be unskippable for scoring-critical concepts?** With −0.25, guessing below ~20% is mathematically wrong — but "Saltar" lets users skip the baremo/confidence lesson entirely. Is a skipped onboarding a converted user or a confused one who will blame the app for net-score surprises?
