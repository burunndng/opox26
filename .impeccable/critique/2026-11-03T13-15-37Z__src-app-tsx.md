## Design Specificity Verdict

**Authored for this product — with one exception.** Baremo formula inline (`+1A / −0,25F / 0B`), item pacing against per-type time budgets, confidence ladder `0–3`, hint ladder revealing *Base legal* before *Fragmento Atómico Clave*, FSRS readouts, `PretestDiagnosticMap` spatial diagnostics, and the cover→generate→reveal→options staging (retrieval before recognition rendered as interaction) are un-portable. **Exception:** `JevLabModal` reads as a generic LLM API console — swap the logo and it ships in a developer tool. Secondary drift: English scaffolding ("confident-wrong", "Modo A/B", "Cover & Generate") is internal vocabulary, not the user's.

---

## What's Working

1. **The staged retrieval flow is the product.** cover → free-recall → reveal → options plus the two-level hint ladder is progressive disclosure serving germane load — authored learning science, not decoration.
2. **Session trust infrastructure.** Autosave every step, JSON export, save/pause, paused-session banner with confirm-before-discard, deterministically audited queue (`scheduler.ts:268`) — the #1 emotional requirement for exam prep.
3. **The repair loop closes.** AnalyticsStrip → ErrorRepairStudio filtered tabs → re-test. The product routes failures back into study; most competitors stop at the score.

## Priority Issues (ordered by importance)

**[P0] Dead-end renderers: `retrieval_prompt` and `pretest_item` have no block in ActivityRunner.**
- **What:** Both are valid `ItemType`s (types.ts:36-37), seeded (4 + 2 items), and scheduled into study blocks (`scheduler.ts:272` foundationalTypes), but ActivityRunner.tsx has render blocks only for cover_and_generate_mcq, cloze, contrast_card, number_sort, spot_error, two_tier, exception_tree/fact_variant. **No input, no button, no message.** Keyboard dead: `retrieval_prompt` not in `hasPositionalOptionShortcuts`; `pretest_item` options array is empty → `optionIdAtPosition` undefined. Mouse users escape only via back arrow; keyboard users press `0`/`B` → forced blank (0 pts) — in pretest mode recording a fabricated omission.
- **Why it matters:** Task completion impossible = definition of P0. Reachable mid-SRS-session; pretest silently produces garbage data. Screen-reader users tab into silence (no aria-live distinguishing "broken" from "loading").
- **Fix:** Free-text self-assessment block for both types (textarea → "Ver respuesta" → self-grade), mirroring MicroLessonRunner.tsx:82. Enforce invariant: exhaustive `Record<ItemType, Renderer>` map so a missing renderer fails at compile time, plus a visible "Tipo sin soporte" fallback card.
- **Command:** `/impeccable harden`

**[P1] English jargon in a Spanish UI — starting at onboarding minute 0.**
- **What:** OnboardingModal.tsx:25 teaches 'Fallar con confianza máxima se marca como "confident-wrong"'; recurs in AnalyticsStrip:70, ErrorRepairStudio:229, PretestDiagnosticMap:150, CalibrationAnalytics:89, plus "Generativo: ON/OFF", "Drill Sniper Activo", "Cover & Generate", JevLab "Jev Decision Engine"/"Output tokens: Free".
- **Why it matters:** Match-system-and-real-world scores 2/4 for this reason alone; the first teaching moment is in a foreign language.
- **Fix:** Spanish primary term everywhere — *"error con confianza máxima"* — English parenthetical on first encounter only. Rename Drill Sniper/Modo A-B to user-experienced descriptions. Spanish labels in JevLabModal except where the user must match a provider payload.
- **Command:** `/impeccable clarify`

**[P1] `StudySetup` presents 6–7 competing choices at the front door.**
- **What:** Recommended default card + 4 mode cards + "Más formas" expander + "Estudio guiado" + scope select + topic selector, all visible, all peers. The smart default is visually just a 7th card — it adds a choice instead of removing one.
- **Why it matters:** Exceeds Cowan's 4-item limit on the most-returned-to screen.
- **Fix:** Single primary CTA ("Empezar sesión recomendada · 20 ítems"), 2 visible secondary cards, rest under "Más formas", scope/topic demoted to inline text controls beneath the CTA.
- **Command:** `/impeccable distill`

**[P2] Two visual systems and a drifting primary color.**
- **What:** Tokenized panels (`#0c0f17/#121722/#20293a`) coexist with raw `slate-900/950/800`; primary actions appear in blue-600, indigo-600, amber-600, emerald-600 depending on file.
- **Why it matters:** Users build a color→meaning map; drift breaks it every screen transition. Consistency 2/4, Aesthetics 2/4.
- **Fix:** One token set everywhere; indigo-600 as single primary (already the Navbar wordmark color); amber/emerald/rose reserved strictly for status. Sweep modals onto tokens in the same pass.
- **Command:** `/impeccable colorize`

**[P2] Help modal contradicts the keyboard; destructive guard levels inconsistent.**
- **What:** HelpShortcutsModal:20 teaches `0,1,2,3` = confidence rating, but ActivityRunner:822 during `stage === 'answering'` makes `0`/`B` fire `handleBlankSubmit()` — immediate, irreversible, and undocumented. Meanwhile "Reparar Todos" (ErrorRepairStudio:179) and "Marcar como reparado" (L369) fire with no confirmation while discard got one.
- **Why it matters:** The app punishes users who read its own help; a mis-click bulk-closes errors still being studied.
- **Fix:** Add `{ key: '0 / B', desc: 'Dejar la pregunta en blanco (0 pts)' }` to help; qualify the `0,1,2,3` entry "tras responder"; confirm on "Reparar Todos" when `filteredErrors.length > 5`. Keep single-item "Marcar como reparado" unconfirmed.
- **Command:** `/impeccable harden`
