## Design Specificity Verdict

**Specific in domain model and language; interchangeable in chromatic shell.**

The product identity is real: "OposiLab · Laboratorio Cognitivo," Spanish UI for Seguridad Social oposiciones, the three-job nav (Temario / Estudiar / Mis fallos), the paused-session resume banner, high-contrast mode per spec §14, and the cloud/local-first framing. The domain language ("fallos", "bloque específico", "repaso espaciado") grounds it in the opositor's world.

However, the visual execution is a generic dark Tailwind admin shell: `bg-[#0c0f17]`/`#121722` cards, slate-indigo-rose accent palette, `rounded-lg` cards everywhere, small utility text. Stripped of the Spanish copy it could pass for any admin dashboard. The "laboratorio cognitivo" subtitle isn't backed by deliberate visual character — no custom illustration, no distinctive motif beyond the indigo Scale icon, no sense of the real usage scene (early morning, tired, phone in hand). Detector corroborates: 3 "AI color palette" flags (indigo gradients, cyan-on-dark) are the most recognizable AI-UI tells.

**Verdict:** Domain-specific where it counts (language, structure, accessibility scaffolding); category-interchangeable in color, typography expression, and density. Missed opportunity: lean into "laboratorio cognitivo" with intentional visual character instead of default dark-dashboard.

## Overall Impression

A capable, domain-serious Operate-mode tool whose shell is competent but cautious: strong loading/error scaffolding, clean three-job navigation, real accessibility bones (high-contrast mode, focus rings, `aria-live` skeleton). The biggest gap is that the visual language doesn't earn the product's specificity — it looks like a template, not a cognitive lab built for tired opositors. The detector's 10 findings (7 contrast, 3 palette) confirm the shell needs hardening before it can match the domain sophistication underneath.

## What's Working

1. **Accessibility scaffolding is genuine** — high-contrast mode (spec §14) with reinforced borders and `focus-visible` rings, `aria-busy`/`aria-live="polite"` boot skeleton, `sr-only` status text, color-never-only-signal (icon + text labels on status). These are deliberate, not accidental.
2. **Clear information architecture** — three primary jobs (Temario/Estudiar/Mis fallos) with advanced tools tucked into a "Más" drawer; mobile secondary bar mirrors desktop; paused-session resume banner on Dashboard. A first-timer can tell what the app does within 5 seconds.
3. **Plain, actionable Spanish copy** — "Reintentar conexión", "No se pudo conectar con el servidor local", "Reanudar sesión" are specific and helpful rather than generic "Error" / "OK".

## Priority Issues

**[P1] Gray-on-color low-contrast text (7 instances across 5 components).**
- **What:** Detector found `text-slate-950`/`text-slate-300` on `bg-amber-600`/`bg-emerald-600` in ContentStudio.tsx (1527, 1716), ErrorRepairStudio.tsx (359, 410), ItemBank.tsx (141), MicroLessonRunner.tsx (207, 285). Washed-out gray on colored surfaces falls below usable contrast.
- **Why it matters:** WCAG contrast breach; small captions on colored badges become unreadable, especially for low-vision users and on mobile glare. Sam (accessibility) cannot rely on color-coded status.
- **Fix:** Replace gray text on colored backgrounds with white/near-white or a darker shade of the background color; ensure ≥4.5:1 for normal text, ≥3:1 for large/UI text.
- **Suggested command:** `/impeccable audit`

**[P2] No confirmation on destructive session actions.**
- **What:** Dashboard's "Descartar sesión" uses a bare trash icon button with immediate `localStorage` deletion — no confirmation dialog, no undo.
- **Why it matters:** A misclick loses an in-progress session; violates error prevention and user control. Riley (stress tester) can destroy data with one tap.
- **Fix:** Add a confirmation dialog (or an "undo" toast with a short window) before discarding a session.
- **Suggested command:** `/impeccable harden`

**[P2] Primary actions lack keyboard shortcuts; accelerators hidden.**
- **What:** The only keyboard affordance is `?` → HelpShortcutsModal. No shortcuts for starting a session, switching tabs, or dismissing modals beyond Esc. Accelerators exist only inside a modal the user must discover.
- **Why it matters:** Alex (power user) cannot work efficiently; every repeat action requires mouse navigation through the same flows. Flexibility heuristic = 2.
- **Fix:** Add direct keyboard shortcuts for the top 3 primary actions (e.g., 1/2/3 for Temario/Estudiar/Mis fallos, Enter/Space to start) and surface them inline rather than only in the `?` modal.
- **Suggested command:** `/impeccable harden`

**[P3] No onboarding or empty-state guidance for first-time users.**
- **What:** A first-timer lands on StudySetup with practice options and zero guidance on which to pick; "Modo A / Modo B" and confidence calibration surface unexplained. Help covers shortcuts only. No empty state when nothing is due.
- **Why it matters:** Jordan (first-timer) learns the mental model only after making errors — too late to build trust in a precision tool. Help heuristic = 2.
- **Fix:** Add a short first-run onboarding (~60 s) demonstrating confidence calibration on a practice item, plus empty states and Mode A vs B tooltips.
- **Suggested command:** `/impeccable onboard`

## Persona Red Flags

**Alex (power user) — primary action: run a fast SRS due session.**
- No keyboard shortcuts for primary actions; must click through Navbar each time. `?` shortcuts are hidden behind a modal.
- Session save/pause requires modal clicks, not a single hotkey, despite being a repeat-user flow.
- Cannot experiment with baremo/penalty settings mid-session (locks after first answer).

**Jordan (first-timer) — primary action: start first practice session.**
- Lands on StudySetup with practice-mode options and zero guidance on which is "the" choice; smart default is present but unexplained.
- "Modo A / Modo B" and confidence calibration appear with no prior introduction; learned only after encountering them (or making errors).
- No empty-state guidance when nothing is due — unclear what to do next.

**Sam (accessibility-dependent) — primary action: review errors via keyboard/screen reader.**
- `text-[10px]`/`text-[11px]` captions below comfortable reading size; `text-slate-500` on dark card surfaces (`#121722`/`#182030`) ≈ 3.2–4.3:1, below the 4.5:1 small-text threshold (Assessment B; detector flagged gray-on-color but not scale).
- Modals (from Navbar flow) lack verified `aria-modal`/focus trapping in the shell review; tab can escape an open dialog.
- Color-coded status (emerald/rose/amber) carries meaning without sufficient redundant text in several small badges.

## Minor Observations

- Boot loading skeleton is well done (`aria-busy`, `aria-live="polite"`, `sr-only` "Iniciando OposiLab MCQ Trainer…").
- Toast auto-dismisses after 5 s — reasonable, non-blocking.
- High-contrast toggle is a real accessibility feature, not a cosmetic afterthought.
- `font-legal-serif` headings nod to the legal domain but body stays sans, so the "legal" character never fully lands.
- Detector's 10 findings are actionable (7 contrast + 3 palette), not false positives — unlike the prior run which dismissed them.
