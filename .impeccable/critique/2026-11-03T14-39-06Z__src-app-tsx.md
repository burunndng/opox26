# Design Specificity Verdict

## LLM assessment
**Specific core, generic edges — and the edges are visible precisely where the user goes to study failures.** The answering experience is unmistakably authored: live Nota Neta while answering, locked baremo pill after the first answer, in-session break-even tuition, "Dejar en blanco" as a keyboard-first citizen, legal basis on every stem, serif legal typography for stems, trap taxonomy in Spanish, Plazos as its own drill. Peak-end is engineered: the summary screen converts every failure into an action and reframes a blank as a tactical decision.

The periphery disagrees with the center: two visual dialects (token trio vs bg-slate-900/border-slate-800), mode colors leaking into CTA roles (indigo / amber-600 / rose-600 / sky-600 for the same "start session" verb), untranslated English analytics labels ("Lapse rate", "Item Bank"), a hardcoded "OposiLab SS Tema 7" chip, Quizlet named in CreateTopicModal, and vocabulary drift (tema/set/reactivo/ítem for one concept).

## Deterministic scan
4 findings total across 23 files (0 errors, 0 advisories, all `warning`): 3 × `ai-color-palette` and 1 × `gray-on-color`. Per-file scan sums exactly match the tree scan (no truncation). The three ai-color-palette hits (ActivityRunner:1296, JevLabModal:236, PretestDiagnosticMap:86 — all indigo accents) were contrast-verified by assessment B: 5.98:1, 10.12:1 and 17.85:1 — all pass WCAG AA and are the deliberate documented token, so they read as false positives as slop accusations. # Overall Impression
The core study loop is Design-Director quality and keeps getting better: the previous critique's dead-ends, trap dialogs, unlabeled fields and drift all read as fixed, and the reviewer validated them without being told. The score barely moved (26 → 27) because with the blocking layer solved, the reviewer's attention moved to consequence-level issues: an invented pass/fail verdict on the summary, an invisible timer, silent data-loss failures, and the unfinished periphery. The single biggest opportunity: make the whole app as disciplined as the answering card.

# What's Working
1. **The baremo isn't explained, it's inhabited** — penalty context ambient at every decision (locked pill, live net score, keyboard blank, session-end break-even tuition). The most product-specific system in the codebase.
2. **Metacognition with integrity — confidence 0–3 drives FSRS, repair queue and calibration UX; hints and lucky guesses are disclosed, not hidden. The UI asks the user to be honest and honors honesty by using it.**
3. **A real, documented keyboard-first loop** (1–4, 0/B, H, Space, ? , Alt+1–3) with kbd chips and a truthful-now shortcuts modal — rare depth, right for the audience.

# Priority Issues

**[P1] One product, two visual systems (+39 dead classes)**
- Problem: Token trio (#121722 family) vs slate-900/border-slate-800 dialect across ~6 surfaces; same verb rendered in indigo/amber-600/rose-600/sky-600 depending on screen; and **39 occurrences of nonexistent Tailwind shades** (`slate-750`/`slate-850` in ActivityRunner, ContentStudio, ExportSettingsMethodModal, HelpShortcutsModal — verified: Tailwind has no such steps and index.css defines none, so borders render as *nothing*).
- Why: Operate-mode contract is consistency; invisible borders read as broken, and high-contrast theming can't reinforce what isn't there.
- Fix: map every slate dialect class to the token trio; replace fake shades (free wins — borders where none render); one primary hue for CTAs, rose/amber demoted to semantic-only. 
**[P1] Invented verdicts poison the engineered peak**
- Problem: summary shows a pass/fail badge against a hardcoded 50% "cut-off" — for a formative 12-question Plazos drill it still can say ""No superas el corte"" — under an unconditional green trophy regardless of result.
- Why: peak-end; the summary is the only guaranteed peak, and a rose badge on an arbitrary threshold is emotional violence with zero basis.
- Fix: mode-aware verdicts (formative drills get mastery copy, never cut-off language); trophy color coupled to result; if a cut-off stays, anchor it to real data and say how it is computed.

**[P1] The pacing timer is invisible while it counts — and mis-anchored**
- Problem: StudySetup promises an adaptive "cronómetro de ritmo"; the control lives in a "Más opciones" popover whose dropdown lacks a `relative` ancestor (anchors to page top-right), the count is not shown during answering, has no urgency state, and silently clamps to 0.
- Why: the only time-pressure feature in a product about exam pacing; a feature that exists but is not perceived is worse than absent.
- Fix: subtle persistent countdown chip in the answering card (color state on the last 25%), decided zero-state, fix the popover anchor.

**[P1] Silent failures betray the local-first promise**
- Problem: `recordAttempt` failures caught with console.error only; InterleavedBlockModal's catch does nothing user-visible; ItemBank delete/validate have no error surfaces.
- Why: in an app whose selling point is "your data lives here", a failed save must be louder than a console line — the user thinks the attempt registered.
- Fix: reuse the toast system for record/export/audit failures; queue-and-retry attempts before advancing feedback.

**[P2] Vocabulary drift and copy leaks**
- Problem: tema/set/reactivo/ítem for one concept; untranslated labels ("Lapse rate", "Item Bank"); hardcoded "OposiLab SS Tema 7" chip; "1 preguntas" dead plural ternary; "AzAR" typo; Quizlet named; emojis inside option texts.
- Fix: one Spanish noun per object, translate analytics labels, delete the platform name, pluralization, copy sweep.

**[P2] window.confirm × 3 in a styled-dialog world**
- Dashboard discard, ErrorRepair bulk repair, ItemBank delete — OS chrome at emotional peaks; replace with the existing styled-dialog pattern (focus trap already available).
